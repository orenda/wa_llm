## Goal

Define the small, pure contract that the scraper, reconciliation core, and Drive adapter will share. Implement a reversible Markdown codec and metadata decoding with golden tests. No browser, network, disk I/O, or sync orchestration in these modules.

## Deliverables

1. **`docs/FORMAT.md`:** The exact version-1 metadata fields and Markdown block grammar, with one complete transcript/sidecar example. Explain delimiters/escaping, line endings, ownership of Notes/prefix bytes, and failure behavior. Message IDs stay in the sidecar, never in visible text or hidden per-message Markdown comments. Define what the codec can recover and what it cannot infer without metadata.
2. **Normalized TypeScript data:** Account/chat/message identity; explicit verified source sequence/anchors versus unknown order; sender identity separately from display name; timestamp display/precision and optional known instant; text and attachment descriptors. Include explicit pending/unavailable/unsupported/opaque states and coverage segments/gaps. These are observations and data types, not a scraper or algorithm for joining history.
3. **Versioned metadata codec:** Serialize/validate metadata and produce an explicit recovery-required/error result for invalid JSON, unsupported versions, missing required state, or a mismatched expected account/chat/destination/generation. Track observed source baselines separately from the baseline represented by saved wording and the committed rendered-block fingerprint. Store tombstones and attachment slots without implementing their reconciliation. Do not silently manufacture empty valid state.
4. **Markdown codec:** Render generated message blocks and parse them back without confusing body text with structural boundaries. Preserve supplied user-owned prefix/Notes bytes exactly. No supplied Notes means no generated Notes. Parse message content independently of IDs: the codec must not assign IDs by matching text/sender/time. Ambiguous or malformed structure produces an explicit error, preserving the original input for the caller.
5. **Golden fixtures and unit tests:** Assert semantic round trips and exact expected output, including duplicate-looking messages, user prefix bytes, unknown content, and failures. Keep both the format and code compact and explain any non-obvious escaping rule.

Suggested scope: `src/model.ts`, `src/format.ts`, one metadata helper if it materially simplifies validation, `tests/format.test.ts`, and `tests/fixtures/format/`. A couple of direct modules are sufficient; no schema framework, generic document engine, or new dependencies. Leave the current extension shell, harness, package files, and CI unchanged unless a concrete compatibility issue is reported to the coordinator.

## Required tests

| Case | Expected behavior |
| --- | --- |
| Two messages with equal sender/time/text but distinct supplied IDs | Retain both blocks and metadata records; no text-based identity or deduplication. |
| Unicode/RTL, multiline text, blank lines, fenced code, sender-looking headers, `## Notes`, and `## Transcript` in a body | Round-trip correctly; content cannot become structure. |
| Existing Notes/prefix with blank lines, CRLF, and non-ASCII content | Preserve its original UTF-8 bytes; do not normalize or reserialize the prefix. |
| No Notes supplied | None is created. |
| Missing or minute-only timestamp/timezone | Preserve known precision/uncertainty; invent no seconds, UTC offset, or chronological order. |
| Unknown attachment descriptor or incomplete source observation | Retain explicit limitation/state; no fake file, link success, verified identity, or complete coverage. |
| Invalid JSON, wrong format version, absent state, wrong expected binding | Explicit error/recovery-required result; no ID guessing, metadata rebuild, or overwrite plan. |
| Malformed or ambiguous Markdown | Explicit parse error; original content remains available unchanged. |
| Same input rendered repeatedly | Deterministic output; correct relative references and no duplicate blocks. |

Relevant edge cases: H03, H07, H09, M01–M03, M07, M09, X04. These tests cover their data/format aspects only; do not claim history loading, downloads, or recovery transactions work yet.

## Out of scope

No OAuth, Google/WhatsApp requests, DOM access, filesystem writes, jobs, retries, browser permissions, missing-sidecar reconstruction, Download/Edit reconciliation, or migrations from an invented legacy version. Do not build the future modules to exercise these types. This ticket establishes the contract for those later assignments.
